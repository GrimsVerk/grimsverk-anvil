## Needs planning

**R1003's acceptance rows — small, and sequenced after the `convert`
milestone builds.** OD-8 grants BL-9's default: a value whose parse is not a
finite float (`nan`, `inf`, `-inf`, overflowing literals such as `1e400`) is
"a value that is not a number" under R4, same named error, same streams and
exit. The `convert` plan (`docs/plans/oracle/od5-convert-cli.md`) already
carries the guard itself in its slice 1 contract — `parse_value` raises
`NotANumberError` on a non-finite result — so **no code work is commissioned
by this ruling**. What R1003 adds is the §13-layer observation the plan lacks:
two rows in `acceptance/S3.sh` —

- `anvil nan km mi` — standard error names `nan`;
- `anvil 1e400 km mi` — standard error names `1e400`;

each asserting a non-zero exit and empty standard output, exactly like the
script's existing seven cases. This is the same shape and position as
`od1-output-precision`: a small plan under `docs/plans/oracle/` citing OD-8,
claiming `covers: [R1003]`, buildable only once `acceptance/S3.sh` exists.
`coverage.sh` will report R1003 as NOT PLANNED until that plan lands — that
report is correct, not a defect.
