## Needs planning

**The `convert-batch` milestone plan (R6), now fully unblocked.** BL-10 and
BL-11 were the HIGH uncertainties that stopped it; OD-9 and OD-10 rule them,
so the planner now derives instead of guessing:

- **`covers:`** claims `[R6, R1004, R1005]` — the two oracle requirements
  landed this run and live in this milestone; no other plan will ever carry
  them.
- **Invocation** comes from **R1001** (OD-5): `anvil --batch` reads standard
  input and accepts no positional arguments.
- **The reader** comes from **R1004** (OD-9): a request line is exactly three
  whitespace-separated tokens — value, from-unit, to-unit — surrounding
  whitespace ignored, blank or whitespace-only lines skipped silently, any
  other token count a failed line. No comments, no header, no flags inside a
  line.
- **The writer** comes from **R1005** (OD-10): one stdout line per non-skipped
  request, in input order; success prints through `format_result` identical to
  the single-shot line (OD-4's obligation, now discharged by requirement);
  failure prints `error: ` plus the same `str(err)` message single-shot writes
  to standard error; standard error stays empty; exit non-zero if any line
  failed, else 0.
- **Acceptance script:** `acceptance/S5.sh` compares expected stdout
  whole-line (the shape OD-6 obliged for S1), asserts empty stderr and the
  non-zero exit, and its five-line fixture includes OD-4's ESC-1 precision row
  (`0.1 km m` → exactly `100`) and one invalid line. It additionally runs a
  second stdin document — two valid requests separated by a blank line —
  asserting exactly two output lines and exit 0, the blank-line-skip
  measurement OD-9 names.

**Sequencing:** buildable only after the `convert` milestone
(`docs/plans/oracle/od5-convert-cli.md`) has merged — `--batch` is a usage
error until R6 exists, and the batch writer reuses `format_result` and the
error types that milestone creates.
